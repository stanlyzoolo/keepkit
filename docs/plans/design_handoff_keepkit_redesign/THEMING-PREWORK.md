# Подготовка к темизации (pre-work, без смены UI)

Цель: убрать глобальные стили-`var`, чтобы тема стала значением, а не пакетом.
Ничего визуально не меняется — чистый рефакторинг перед накаткой редизайна.

## Шаги

1. **`internal/ui/theme.go` (новый)** — структура ролей, ровно 10 полей:
   `type Theme struct { Accent, Signal, Ok, Danger, Link, Emphasis, Text, Dim, Border, Surface lipgloss.Color }`
   плюс `OrangeDim` для трека гейджа. `var Default = Theme{…}` с текущими значениями
   (пока старыми — редизайн-палитра придёт отдельным коммитом одной правкой этого блока).

2. **`internal/ui/styles.go`** — все `var XxxStyle = …` превратить в поля
   `type Styles struct { … }` + конструктор `func NewStyles(t Theme) Styles`.
   Правило то же, что сейчас в комментарии палитры: стили строятся только из полей Theme,
   никаких inline-hex.

3. **`internal/model`** — `Model` получает поле `styles ui.Styles` (задаётся в `New()`
   через `ui.NewStyles(ui.Default)`); все обращения `ui.XxxStyle` → `m.styles.Xxx`.
   Механическая замена, ~render.go / textutil.go / mode.go. Функции без доступа к модели
   получают `Styles` (или конкретный `lipgloss.Style`) параметром.

4. **glamour** — `keepkitStyle(dark)` принимает `Theme` и берёт акценты из неё
   (сейчас hex захардкожены в overrides). Пересборка readme при смене темы —
   существующим путём `switchHelpMode`.

5. **Тесты** — паттерн уже есть: `forceColor(t)` + сравнение через
   `termenv.TrueColor.Color(string(theme.X)).Sequence(false)` (см. render_test.go),
   чтобы ассерты не дублировали hex-литералы.

## Не делать сейчас
- Оверлей выбора темы, персист выбора в configdir, набор встроенных тем —
  отдельная фича ПОСЛЕ этого рефакторинга и накатки редизайна.

## Definition of done
- В `internal/` нет обращений к стилям уровня пакета (`grep 'ui\.[A-Z][a-zA-Z]*Style'` пуст,
  кроме `m.styles`).
- Один источник цветов — `Theme`; смена всех цветов приложения = замена одного значения.
- Тесты зелёные без правок ожиданий (визуально ничего не изменилось).
